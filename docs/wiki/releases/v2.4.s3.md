# Release Note: V2.4.S3

## Slice

`V2.4.S3 - Candidate-feature-aware metrics availability`

## User-visible Changes

1. C5 Metrics now adapts to selected candidate architecture features.
2. Metrics/signals that are not applicable are marked as unavailable and cannot be enabled.
3. C5 shows a compact candidate feature summary (`LLM`, `Retrieval`, `Rerank`, `Tool`, `HITL`).
4. Validation now considers only enabled and available metrics/signals.

## Why

To prevent invalid metric setups when candidate architectures do not contain the required pipeline stages.

## Technical Summary

1. Added availability engine in `workspace.registry_store`:
- feature extraction from selected candidates (`mini_graph`),
- requirements mapping for metrics/signals,
- auto-disable of unavailable items.
2. Extended C4/C5 evaluation payload with `candidate_features` and per-item availability fields.
3. Updated frontend C5 metrics UI to show availability reasons and lock unavailable toggles.
4. Added unit/frontend/integration tests for availability behavior.
