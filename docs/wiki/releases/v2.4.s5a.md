# Release Note: V2.4.S5a

## Slice

`V2.4.S5a - Stage-ref-first non-final binding (trace-aware)`

## User-visible Changes

1. C6 now contains a dedicated `Stage bindings (stage_ref)` card.
2. Users can add/edit/remove stage bindings manually:
- `stage_ref`,
- `target_stage` (`retrieval | rerank | synthesis | final`),
- `match_policy` (`primary_only | all_must_pass | best_of`),
- `enabled`,
- `notes`.
3. `Suggest stage refs` proposes rule-based stage bindings from candidate features.
4. Coverage summary is shown per binding (`bound / ambiguous / missing` across candidates).
5. `Save stage bindings` persists bindings and immediately refreshes profile validation context.

## Why

Non-final evaluation metrics require explicit and traceable mapping to candidate pipeline stages.  
This slice removes hidden hardcoded assumptions and makes binding both inspectable and editable.

## Technical Summary

1. Extended evaluation profile/studio schema in `optimizer.workspace.registry_store` with:
- `stage_bindings`,
- `stage_binding_coverage`.
2. Added normalization + dedup for bindings and policy-safe matching logic.
3. Added coverage resolver over candidate `mini_graph` with per-candidate verdicts (`bound/ambiguous/missing`).
4. Extended preflight validation with stage-binding issue codes:
- `stage_ref_missing`,
- `stage_ref_unresolved`,
- `stage_ref_ambiguous`,
- `stage_ref_multi_match`,
- `stage_ref_policy_violation`.
5. Added API endpoints:
- `POST /api/arenas/{arena_id}/evaluation/stage-bindings/suggest`,
- `POST /api/arenas/{arena_id}/evaluation/stage-bindings/save`.
6. Updated C6 frontend state/types/UI handlers and tests.
