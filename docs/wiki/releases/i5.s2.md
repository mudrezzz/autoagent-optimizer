# I5.S2 - Evaluator Adapter Layer v0

## What Changed

1. Added evaluator adapter catalog in backend.
2. Evaluation state now enriches evaluators with adapter kind, requirements, supported metric refs and budget model.
3. Evaluator x Metric links now include compatibility status and reason.
4. Backend validation rejects enabled incompatible evaluator x metric links.
5. C6 UI shows evaluator adapter metadata and disables unsupported matrix cells.
6. Updated the real C6 screenshot in user documentation.

## Why It Matters

Before this slice, a metric could be assigned to any evaluator visually.
That was misleading because different evaluator methods can score different things.

Now the product explains why a link is possible or impossible:

1. Golden dataset oracle is dataset-driven.
2. LLM judge is semantic and LLM-budget-driven.
3. Executable validator is runtime/test/render-like.

## How To Verify

1. Open a battle workspace.
2. Go to `Evaluators`.
3. Confirm evaluator cards show adapter kind and requirement chips.
4. In `Evaluator x Metric matrix`, confirm unsupported cells show `not supported`.
5. Click `Validate profile`; incompatible forced links should appear as validation issues.
