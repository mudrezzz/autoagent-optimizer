# Release Note: V2.4.S5b

## Slice

`V2.4.S5b - Target-stage-first mapping UX correction`

## User-visible Changes

1. C6 no longer asks users to edit `stage_ref`.
2. Added `Stage mapping` card with:
- `Auto-map stages`,
- per-candidate manual override (`selected node ids`),
- `Save mapping`.
3. Mapping is now shown directly as `target_stage -> candidate nodes`.

## Why

`target_stage` already exists in dataset rows and is the natural user-level contract.
Separate user-facing `stage_ref` was redundant and increased complexity.

## Technical Summary

1. Added stage mapping model in evaluation state:
- `stage_mappings`,
- `stage_mapping_coverage`.
2. Added API endpoints:
- `POST /api/arenas/{arena_id}/evaluation/stage-mapping/auto-map`,
- `POST /api/arenas/{arena_id}/evaluation/stage-mapping/save`,
- `GET /api/arenas/{arena_id}/evaluation/stage-mapping/state`.
3. Preflight validation now uses mapping coverage with issue codes:
- `stage_mapping_missing`,
- `stage_mapping_unresolved`,
- `stage_mapping_ambiguous`,
- `stage_mapping_policy_violation`.
4. Legacy stage-binding endpoints remain as compatibility wrappers.
