# V2.4.S5c - Stage Mapping Wizard Step + De-blocking UX

## Summary

This slice moved `Stage Mapping` out of `Evaluators` into a dedicated wizard step and removed blocking behavior around manual work.

New order:

1. Candidates
2. Datasets
3. Metrics
4. Stage Mapping
5. Evaluators
6. Optimizer Run

## What Changed

1. New left-menu step: `Stage Mapping` (`c5s`).
2. `Evaluators` now contains only:
- evaluator list,
- evaluator x metric matrix,
- profile validation/version actions.
3. `Budget` controls are no longer shown in `Evaluators`; budget remains in `Optimizer Run`.
4. Stage mapping auto-init:
- entering `Stage Mapping` triggers automatic initialization when rows are empty.
5. Manual flow added:
- `Add row`,
- per-row `Delete`,
- editable `target_stage`, `candidate`, `node ids`, `notes`.
6. `Refresh auto-map` is optional re-sync, not mandatory gate.
7. Wizard gating updated:
- `Evaluators` is locked only when non-final diagnostics require mapping and coverage is not ready.

## Backend / API Notes

1. Existing stage-mapping endpoints were reused:
- `POST /api/arenas/{id}/evaluation/stage-mapping/auto-map`
- `POST /api/arenas/{id}/evaluation/stage-mapping/save`
2. No migration of stored data was required.
