# ADR-0005: Continuous Demo Track Policy

- Status: Accepted
- Date: 2026-05-06
- Slice: I0.S3
- Decision Makers: Project team
- Supersedes: N/A

## Context

Проект развивается итеративно. Без синхронного демо:

1. сложно показать реальный прогресс;
2. команда теряет единый демонстрационный сценарий;
3. новые разработчики хуже понимают практическое текущее состояние.

Нужно закрепить обязательное правило: демо развивается параллельно с функционалом.

## Decision

Вводим постоянный demo track как обязательный процесс:

1. У проекта есть единый базовый демо-сценарий.
2. На каждом слайсе демо-сценарий обновляется вместе с функциональностью.
3. Каждый слайс должен иметь runnable демо-шаг (команда/скрипт/flow).
4. Демо не может отставать более чем на 1 слайс относительно реализации.

## Alternatives Considered

1. Делать демо только к релизам.
2. Делать ad-hoc демо без фиксированного сценария.
3. Полностью отделить демо от roadmap.

## Consequences

### Positive

1. Прогресс виден в любой момент времени.
2. Проще проводить внутренние и внешние показы.
3. Повышается качество интеграции между слайсами.

### Negative / Trade-offs

1. Дополнительная дисциплина и документационная нагрузка.
2. Нужно поддерживать демо-артефакты в актуальном состоянии.
